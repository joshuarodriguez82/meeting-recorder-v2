Calendar detail

On the new Outlook web stack the join link, attendee list and invite body are fetched by Outlook's service worker, where page-level reading cannot see them. With this on, the capture reads those responses directly. Chrome shows a "Meeting Recorder is debugging this browser" bar on the capture tab while it runs; it detaches when the capture finishes. Turn it off to capture without the bar — subjects and times still work, detail may not.

How often the extension opens Outlook in a background tab to refresh Upcoming Meetings. Was every 30 minutes in earlier versions, which is why the calendar seemed to open constantly. Default 240 (4 hours). Set 0 to stop it entirely and refresh only with Capture & Send.

How it works

1. You stay signed in to Outlook + Teams in this Chrome (your normal browsing session).

2. On a schedule (or when you click Capture now), the extension opens these URLs in the background:

  • outlook.office.com/calendar/view/day — today's agenda (feeds the Today tab's briefing)
  • outlook.office.com/calendar/view/week (current + next) — feeds the Record tab's Upcoming Meetings list, read as structured events from each meeting's own accessibility label, not scraped text
  • teams.microsoft.com/.../activity — @mentions, replies, missed calls
  • outlook.cloud.microsoft/mail/?folder=focusedinbox — focused inbox (most needs-response items live here)
  • teams.microsoft.com/.../chat — active 1:1 / group chats

3. Each tab waits for content to render, the extension reads it, then closes the tab.

4. The four narrative sources are POSTed together and the LLM parses them into a daily briefing with check-offable action items. Calendar events are POSTed as structured data and go straight into the Record tab's meeting store — no LLM involved, so nothing is lost to a char-budget or a regex guess.

5. The calendar refresh also runs on its own schedule every 30 minutes, independent of the auto-capture toggle above, so Upcoming Meetings stays current even if you never turn that toggle on.

6. Because the scrapes run in YOUR real Chrome (no Playwright), Microsoft's automation detection doesn't fire — your real session cookies authenticate everything.

Diagnose calendar API access

    
Teams meetings show no Join link, every meeting shows Attendees (0), and no invite descriptions come through. All three are the same thing: that detail is not in the calendar grid, so no amount of reading the page will find it. The alternative is to ask the same API Outlook Web itself asks, from inside your already-signed-in session.

    
This checks whether that is possible on your tenant. It tries each candidate endpoint and reports what each one actually did — answered with the fields we need, answered without them, refused our credentials, or could not be reached. Those are kept separate on purpose: an endpoint that returns a tidy empty answer must never be recorded as working.

    
It reads your real calendar and reports none of it — status codes, response sizes, and which field names came back. No subject, attendee, body text, URL or token is included, so the result is safe to share.
