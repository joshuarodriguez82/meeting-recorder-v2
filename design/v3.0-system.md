# Meeting Recorder v3.0 — Design System

A spec, not a marketing doc. Reference for anyone (Claude or otherwise)
picking up the v3.0 work cold. Locks the visual decisions made during
the v2.9 → v3.0 design exploration so we don't litigate them again.

References live in `design/`:

- `v2.9-mockup.html` — Sessions view, current proposal
- `v3.0-record-mockup.html` — Record view, current proposal

If a decision below conflicts with what's in those files, the files are
the source of truth. Update this doc when they change.

---

## 1. Intent

**Build software that doesn't look like it was generated.** The default
shadcn / Tailwind / Inter / indigo / pills / sparkles palette is the
universal tell of AI-built apps. We're rejecting all of it.

What we want it to feel like instead: **Linear, Things, Cron, Stripe
Dashboard.** Professional software made for someone who uses it 8
hours a day. Confident, restrained, dense-but-breathable. The kind of
app that gets featured on laudableapps.com — not because it's flashy,
but because every detail is deliberate.

**Specifically:**

- A real distinctive primary color that's not vanilla indigo
- Sans-serif throughout (no serifs anywhere — tried it, looked like
  a wedding invitation)
- One semantic color system used with discipline (color appears when
  content has meaning, not as decoration)
- Real component shapes (rectangles with small radii, never `999px`
  capsule pills)
- Motion as a system, not isolated transitions
- Microtype obsession (tabular numbers, considered tracking, real
  hierarchy)
- A signature feature (Cmd+K command palette — flagship execution)
- Light primary, calibrated dark as a peer

---

## 2. The hard "don't" list

Each of these is a tell. If we ship any of them, the app reads as AI.

| Don't | Why |
|---|---|
| Indigo / purple primary (`#5b5bd6`, `#6366f1`, `bg-violet-*`) | Every AI tool ships this |
| Pills (`border-radius: 999px`) | The AI-builder default. Capsule everything = template |
| `<Sparkles>` icons or any "✦" decoration | Dead-on AI-app marker |
| Cream / warm paper backgrounds (`#f5e8c5`, `#f4f1ea`) | Tried it — reads as literary, not modern |
| Serif display faces (Newsreader, Source Serif, Playfair) | Same — editorial feel for professional software is wrong |
| Glass / frosted backgrounds (`backdrop-filter: blur`) | iOS marketing site; not a dense data tool |
| Gradient panels or gradient borders | AI flourish |
| Default shadcn 8px corners on every surface | Visual sameness |
| Avatars as colored letter circles | Filler decoration |
| Stock iconography or sparkly "AI" badges | Same |

When in doubt: remove decoration, keep type and spacing doing the work.

## 3. Color system

Light-first. Tokens as CSS variables in `globals.css`. Each one has a
named purpose; no token exists "just in case."

### 3.1 Surfaces

```
--bg:           #ffffff   pure white. Cards, primary content
--bg-soft:      #fafafa   page background. Sidebar.
--bg-muted:     #f4f4f5   input fields, code blocks
--bg-hover:     #f4f4f5   hover state on lists
```

Three layers of depth, achieved with one-step lightness shifts. No
shadows used to imply depth at the page level — only on elevated
surfaces (modals, popovers, dropdowns).

### 3.2 Borders

```
--border:         #e8e8ea   default 1px borders
--border-soft:    #f0f0f2   dividers inside a card
--border-strong:  #d4d4d8   hover / active border accent
```

### 3.3 Ink (text)

```
--fg:         #18181b   body text
--fg-strong:  #09090b   headings, key labels
--fg-muted:   #71717a   secondary text
--fg-subtle:  #a1a1aa   tertiary, timestamps
```

### 3.4 Primary

**Refined blue, not AI-indigo:**

```
--primary:       #2962ff   primary buttons, focus rings, active selection
--primary-soft:  #eaf0ff   subtle backgrounds (callouts, hover-on-primary)
--primary-text:  #1d4ed8   text on light primary backgrounds
```

Distinction from AI-indigo: sits between Cron's slate-blue and Stripe's
sapphire. Saturated enough to register, restrained enough to not be the
visual focus of every screen. Primary action buttons can ALSO use pure
ink (`var(--fg-strong)` as background) — black-on-paper for "Start
recording" reads more sophisticated than blue.

### 3.5 Semantic / meeting-type palette

Color appears when content has meaning. Each meeting type gets a
distinct hue used as a small colored tag on session cards, mode chips,
filter rows, etc.

```
--t-sa:         #6366f1  --t-sa-soft:     #eef2ff
--t-sales:      #d97706  --t-sales-soft:  #fef3c7
--t-exec:       #0f172a  --t-exec-soft:   #e2e8f0
--t-disc:       #0891b2  --t-disc-soft:   #cffafe
--t-sow:        #be123c  --t-sow-soft:    #ffe4e6
--t-status:     #16a34a  --t-status-soft: #dcfce7
--t-tech:       #7c3aed  --t-tech-soft:   #ede9fe
--t-demo:       #ea580c  --t-demo-soft:   #ffedd5
```

These are *content* colors, not chrome colors. Don't use them for
background panels, page headers, or anything that isn't meaningfully
tagged.

### 3.6 Status colors

```
--accent:       #10b981   live signals (live transcript active, success)
--accent-soft:  #ecfdf5   subtle background for live elements
--accent-text:  #047857   text on light accent backgrounds

--signal-red:    #ef4444  recording, overdue, destructive
--signal-amber:  #f59e0b  warnings, attention
```

Status colors map to actual state. A red dot means "recording." An
amber badge means "needs attention." Never use them decoratively.

### 3.7 Dark mode

Not in v3.0 scope unless we explicitly add it later. **Calibrate dark
separately when it ships — don't just invert the tokens.** Pure
inversion creates muddy mid-greys and washes out the primary. When dark
ships, write a parallel token set that's been designed, not derived.

## 4. Typography

### 4.1 Type stack

```
--sans:  "Inter", -apple-system, BlinkMacSystemFont, sans-serif
--mono:  "IBM Plex Mono", ui-monospace, "SF Mono", monospace
```

Inter only. Three weights: 400 (body), 500 (medium), 600 (semibold).
No 700. No serif anywhere. IBM Plex Mono for any tabular data context
(numbers, durations, timestamps, code snippets).

Inter feature settings on globally:

```css
font-variant-numeric: tabular-nums;
font-feature-settings: "cv11" on, "ss03" on;
-webkit-font-smoothing: antialiased;
```

`cv11` = single-story 'g' (cleaner at small sizes). `ss03` = stylistic
ligatures. Both subtle but they make Inter feel less default.

### 4.2 Scale

```
h1: 22px / 1.2  / weight 600 / letter-spacing -0.014em
h2: 15px / 1.3  / weight 600
h3: 13px / 1.3  / weight 600

body:      14px / 1.5
body-sm:   13px / 1.5
label:     12px / 1.4 / uppercase / letter-spacing 0.06em / weight 600
caption:   11px / 1.4
```

Never use display sizes (>22px) for headings within content. Anything
larger is the brand mark or the recording-elapsed clock — both are
special cases.

### 4.3 Microtype rules

- **All numbers use `var(--mono)`** in dense data contexts (lists,
  cards, footers, sidebars). Body prose stays sans.
- **Labels** are uppercase + tracked (`letter-spacing: 0.06em`), 11px,
  weight 600. Used for section headers in cards and tag-row eyebrows.
- **Italic body text** is fine where standard prose uses italic. Don't
  use it for design emphasis — that's a serif move.
- **Pure tabular alignment** on any column of numbers. The
  `tabular-nums` default handles most cases; if a number is in a
  flexbox row with text, wrap it in `<span class="num">` to enforce
  monospace.

## 5. Spacing & layout

### 5.1 Grid

4px base unit. All padding, margin, gap values are multiples of 4.
Use Tailwind's default scale (`gap-2 = 8px`, `gap-4 = 16px`, etc.) but
audit for visual rhythm — three different gap values within one card
is one too many.

### 5.2 Density

Comfortable, not dense. Linear / Things tier:

- Card padding: 16-22px (Tailwind `p-4` to `p-5`)
- Vertical rhythm in lists: 6-8px between rows, dividers as 1px borders
- Sidebar items: 6px padding-y, 12px padding-x (clickable but not dense)
- Form fields: 7px padding-y (slightly more breathable than shadcn default)

Avoid Linear's *information*-density mistake (everything jammed
together). We have time-series data (session lists) where breathing
room helps scanning.

### 5.3 Corners

```
2px   buttons, badges, inputs
4px   tag chips, small flat elements
6px   form controls, dropdowns, nav items
8px   cards, panels, list rows
12px  modals, large surfaces
```

Never `999px`. Never `0px` (sharp edges read as code-editor aesthetic,
not professional software).

## 6. Motion

One curve. Three speeds. Applied consistently across every hover,
state change, transition.

```
--ease:   cubic-bezier(0.16, 1, 0.3, 1)   for everything

--t-fast: 120ms   hovers, focus rings, micro-state changes
--t-base: 180ms   modals opening, list-row clicks, tab switches
--t-slow: 280ms   page transitions, complex state changes
```

### 6.1 Animation rules

- **Hovers** transition `background`, `border-color`, `color` — never
  `transform` (jittery). Buttons can `transform: translateY(-1px)` on
  hover; cards cannot (visual instability across rows).
- **Modal entrance:** opacity + translateY(6px → 0) + scale(0.99 → 1).
  ~200ms. Backdrop fades in 180ms with `backdrop-filter: blur(6px)`.
- **List rows:** no entrance animation on initial mount. Adding a row
  mid-session (e.g. new co-pilot tick) gets a brief background tint
  that fades out over 800ms (`@keyframes seg-fade`).
- **Recording pulse:** the red recording dot pulses with `box-shadow`
  spreading and fading every 1.8s. Subtle, ambient — not a beacon.
- **Wave bars:** during active recording, a small 5-bar waveform
  animates the bar heights independently. 80ms stagger per bar,
  1.1s loop. Used in the hero recording strip and inline next to
  "Recording" labels.

### 6.2 Don't animate

- `border-radius` (CSS animates poorly cross-browser)
- `width` / `height` of grid columns (use `flex` if you need fluid)
- Filter changes (jarring on lists)
- Any property at >300ms unless it's a page transition

## 7. Components

### 7.1 Buttons

| Variant | Background | Border | Use case |
|---|---|---|---|
| `primary` | `--fg-strong` (black) | none | The single most important action on a screen ("Start recording") |
| `accent` | `--primary` (blue) | none | Secondary primary, or "this is a flow action" |
| `ghost` | transparent | `1px --border` | Most actions in lists, toolbars, dialogs |
| `danger` | `--signal-red` | none | Destructive only (Stop recording, Delete) |
| `icon` | transparent | none | Square 26-28px icon-only buttons in dense toolbars |

All buttons: 6px corners, 13-14px font, weight 500, `transition-luxury`
applied.

### 7.2 Dropdowns / selects

**Never pills.** Single rectangle with rounded 6px corners, hover
darkens the border. Optional small label inside the trigger:

```html
<button class="select">
  <span class="select-label">Mode</span>
  <span class="select-value">SA</span>
  <span class="select-caret">▾</span>
</button>
```

The label-inside-trigger pattern is what makes filter dropdowns scan
faster than a plain selection — the user sees both what's being
filtered and what value it has, in one element.

### 7.3 Tags / chips

**For semantic content only.** Meeting types, statuses, client labels.

```html
<span class="tag tag-sa">
  <span class="tag-dot"></span>
  SA
</span>
```

Always: small soft-background fill in the type color + matching dot
prefix + uppercase 600-weight text. 4px corners. Padding 2/8px.
Always presented in pairs or triples — a single solo tag reads as a
mistake.

### 7.4 Cards

```css
background: var(--bg);
border: 1px solid var(--border);
border-radius: 8px;
padding: 16px 18px;
```

Hover state: `border-color: var(--border-strong)` + `box-shadow: var(--shadow-sm)`.

Active recording cards get a 2px left-border in `--signal-red` and a
left-fading gradient overlay at 3% opacity.

### 7.5 Status indicators

**Small colored dots + text, not big badges.** Examples:

- Live transcript: 6px dot in `--accent` + "Live transcript active"
- Recording: 8px pulsing dot in `--signal-red` + "Recording" + clock
- Unread / attention: text count in `--accent-text` color, weight 600

### 7.6 Modals / popovers

- 12px corners
- `box-shadow: var(--shadow-lg)` — soft, offset, dark
- Backdrop: `rgba(0,0,0,0.18)` + `backdrop-filter: blur(6px)`
- Entrance: scale + opacity + translateY (see Motion)
- Max-width: 560px for command palettes, 720px for content modals

### 7.7 Command palette (Cmd+K)

**Flagship feature for v3.0.** Mockup in `v2.9-mockup.html`.
Specifics:

- Triggered by Cmd+K (Mac) / Ctrl+K (Windows)
- Open by clicking the "Quick find..." hint in the sidebar
- Search input is 15px, weight 400, uses sans
- Results grouped (Recording / Recent / Jump to) with italic group labels
  — but italic-sans, not serif. (No serif anywhere, see §2.)
- Each row: icon (14px lucide) + name + hint + keyboard shortcut
- Selected row gets `var(--bg-soft)` background + 2px left-border
- Escape closes; ⌘K toggles

Implementation note: integrate with `cmdk` library if it slots in
cleanly; otherwise build from primitives. Either way the modal feels
the same.

### 7.8 Iconography

Lucide icons only. **Thin stroke** (`stroke-width: 1.75`) — the default
`2` reads heavy at the small sizes we use. Inline SVG, not bitmap.
14×14 default size in nav, 13×13 in dense rows, 16×16 in primary
actions.

Icons appear where they help comprehension (a recording dot, a chevron,
a checkbox). Never decorative. No icon-soup in cards.

## 8. States

### 8.1 Hover

Every interactive element has a hover state. The transition is exactly
`var(--t-fast) var(--ease)`. The change is one of:

- Background lightens to `--bg-hover`
- Border darkens to `--border-strong`
- Adds `var(--shadow-sm)`

For primary buttons: opacity drops to 0.88. For icon buttons: background
appears (`--bg-muted`). For cards: border darkens + small shadow.
**Never combine all three** on a single hover — pick one or two.

### 8.2 Focus

Visible focus ring on every focusable element:

```css
outline: 2px solid var(--primary);
outline-offset: 2px;
border-radius: inherit;
```

Use the `:focus-visible` pseudo so mouse users don't see it on click,
keyboard users do.

### 8.3 Active / pressed

`transform: scale(0.98)` on primary buttons. Quick and grounded — feels
like a real click. Don't apply to ghost buttons (too subtle to register).

### 8.4 Disabled

`opacity: 0.5` + `cursor: not-allowed` + remove hover effects. Don't
recolor; the desaturation does the work.

### 8.5 Empty states

Every list view has a designed empty state. Three components:

1. One sentence explaining what shows up here ("Your meeting history
   will live here.")
2. A subtle visual element — usually a 24×24 lucide icon, never an
   illustration
3. A primary action or hint ("Start your first recording from the
   Record tab.")

Empty states are voice opportunities. Brief, specific, never generic.

## 9. Layout patterns

### 9.1 Two-column split (list + detail)

The pattern used on Follow-ups, Commitments, Decisions, Sessions. Left
column is the list; right is the detail of the selected item. The
right column is **sticky** — stays in viewport as the user scrolls the
left.

```
grid-template-columns: 1.5fr 1fr   (60/40)
```

Adjust to 1.4/1 when the detail has rich content (forms, multiple
sections). Never 50/50 — the list deserves more room.

### 9.2 Three-zone main content (Record view)

The Record view stacks three zones vertically:

1. **Recording hero** (top) — meeting + clock + controls in a single
   prominent card
2. **Live grid** (middle) — transcript and co-pilot side-by-side, 60/40
3. **Upcoming meetings** (bottom) — calendar tiles in a responsive grid

When not recording, zone 1 collapses to a recording-options panel.

### 9.3 Sidebar

Fixed 240px wide. Brand mark + quick-find hint + recording strip (when
active) + nav + footer (storage + Settings link).

Nav is grouped: top-level items (Sessions, Record), then "Action"
group (Follow-ups, Commitments, Decisions), then "Workspace" group
(Search, Ask, Clients, Engagements, Insights, Prep brief). Group
labels use the small caps style.

## 10. Migration plan

Five phases. Each ships as its own dot release (or PR within one).
Functionality changes are explicitly forbidden in design phases.

### Phase 1 — Token foundation (v2.9.x, no visible change)
- Add all CSS variables from §3, §4, §5, §6 to `src/app/globals.css`
- Wire into Tailwind's theme config as extended colors
- Load IBM Plex Mono via `next/font` alongside existing Inter
- Add `--ease` utility class
- **Risk:** zero. Nothing references the new tokens yet.

### Phase 2 — Sidebar (v3.0 part 1)
- Migrate sidebar to new tokens
- Wider 240px width (was 60)
- New nav grouping + small-caps group labels
- Brand mark restyle (no logo glyph card — just text)
- New Cmd+K quick-find hint

### Phase 3 — Sessions list (v3.0 part 2)
- Card style migration (new corners, hover state, recording indicator)
- Meeting-type tag system applied to existing summary metadata
- Filter row converts pills to dropdowns
- New group-divider style (Today / Yesterday / etc.)

### Phase 4 — Record view (v3.0 part 3)
- Hero recording strip (the big one with clock + wave)
- Live transcript panel restyle (new typography, speaker color coding)
- Co-pilot panel restyle (matches sessions design)
- Upcoming-meeting tiles

### Phase 5 — Detail surfaces (v3.0 part 4)
- Session detail dialog
- Follow-ups / Commitments / Decisions detail panes (already sticky;
  just needs token migration)
- Settings cards (token migration; structure unchanged)

### Phase 6 — Motion + microtype pass (v3.0 final)
- Apply `transition-luxury` to every hover state
- Audit number formatting; wrap with `<span class="num">` where needed
- Wave bar component for recording state
- Recording pulse animation
- Focus rings everywhere
- Empty state copy + icons
- Cmd+K command palette implementation

**At each phase boundary:** TypeScript clean, build succeeds, no
runtime errors. Take screenshots. Compare before/after. If functionality
broke, the phase is wrong; back out.

## 11. Verification — when is v3.0 "done"?

Subjective. But the checklist:

- [ ] No `border-radius: 999px` anywhere except real circles (dots, avatars)
- [ ] No `<Sparkles>` icon in the codebase
- [ ] No serif faces loaded or used
- [ ] No indigo / purple primary
- [ ] Inter Tight is the only display face if any — IBM Plex Mono for numbers
- [ ] Every interactive element has a focus ring
- [ ] Every list view has a designed empty state
- [ ] Cmd+K opens a command palette
- [ ] Recording state has visible motion (pulse + wave bars)
- [ ] Mockup files in `design/` match the implementation
- [ ] Side-by-side screenshot diff against v2.9 looks like a deliberate redesign, not a reskinned shadcn template

When all of those are checked, v3.0 ships.
